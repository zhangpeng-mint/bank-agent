# BankDev Agent 项目概览

## 1. 目标与原则

BankDev Agent 是面向银行核心系统、中间封装层和 DFBM 的本地优先研发分析助手。它读取经授权的文档与只读代码快照，以可引用证据辅助需求分析、跨仓库定位、影响分析、测试设计和后续联调排障。

核心原则：证据优先、最小权限、本地优先、渐进增强、确定性分析优先于模型猜测。任何结论必须标记为“已确认事实”“基于证据的推断”或“待确认问题”。

## 2. 当前资料边界

截至本设计形成时，当前工作区没有三套系统的代码、接口清单、历史需求或脱敏日志。因此：

- 本文不假设仓库目录、类名、接口编号格式、通信协议或所有请求都经过同一路径。
- “银行核心系统—中间封装层—DFBM”只是候选拓扑，实际边由代码、配置、接口文档和运行证据确认。
- Apache Fineract 仅作为可能出现的依赖，不预设其版本、改造方式或覆盖范围。
- 支付网关和风控不在本项目的核心范围。

待接入资料包括：三个系统的只读 Git 快照与 commit、构建文件、配置样例、OpenAPI/接口表、MyBatis XML、历史方案、脱敏日志、术语表、错误码表和已完成需求的标准答案。

不依赖上述资料即可推进：元数据规范、索引协议、证据模型、工具接口、安全策略、测试框架和模拟语料。

## 3. 主要使用场景

1. 以业务词或接口编号检索文档，返回版本、章节和可点击出处。
2. 从接口入口追踪 Controller/注册器、Service、RPC/HTTP 客户端、Mapper/SQL，并显式呈现断点和歧义。
3. 对新需求形成有证据的现状、影响、方案、测试与待确认事项报告。
4. 比较接口或文档版本，识别字段、约束和错误码变化。
5. 后续结合脱敏请求、响应和日志，将静态候选链与真实运行链对照排障。

## 4. 范围分期

### MVP 范围

- 业务知识检索。
- Java 代码检索和初步调用链分析。
- 基于文档与代码证据的需求分析报告。
- CLI 为主，FastAPI/MCP 作为同一应用服务的薄适配层。

### 后续范围

- 向量语义检索、复杂图分析、运行时日志关联、OpenTelemetry 对照、接口版本治理。
- 经审批的测试执行和代码修改建议；默认永不直接修改业务仓库。

### 明确不做

- MVP 不建设复杂 Web UI、完整多 Agent 平台、生产数据库连接、自动提交业务代码或未经授权的云端资料上传。
- 不替代 Codex/Claude Code 的通用文件编辑、终端执行和代码生成能力；只提供银行域知识、跨仓库索引、证据与策略边界。

## 5. 成功定义

系统价值不以报告长度衡量，而以真实定位率、调用边准确率、关键影响召回率、引用有效率、零臆造率和开发者节省时间衡量。详细指标见 `08-security-and-evaluation.md`。
